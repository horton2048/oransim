# Augur · 上市预测 — open-design 输入包 · 从这里开始

这是一份喂给 **open-design**（`nexu-io/open-design`，本地优先的开源版 Claude Design）的输入 bundle，用来从零设计 **Augur 上市预测** 的单一 C 端前端。

闭环：**open-design 出几套备选设计 → 你挑一套 → 把产物丢回 Claude Code（我）→ 我据此改后端、接真数据跑通**。

> 产品名：**Augur**（中文界面也用 Augur，不再用中文品牌名）。
> **界面任何地方都不要出现 `oransim`**——那是旧项目代号；`/api/*` 是后端实现路径，不是品牌名，保持不变。

---

## 这个产品是什么（一句话）

用户输入**任何**一个产品想法，得到一份**诚实标注**的上市预测——会不会火、谁会买、什么会出问题。

核心思想：把过去的「**保安式守门人**」（只认 15 类消费品、其它硬拒）换成「**分诊台**」——任何想法都不拒，按**可信度**分流三档：

| 档 | 名字 | 什么时候走这档 | 产出形态 |
|----|------|----------------|----------|
| **A** | 校准模拟 | 有校准语料的消费垂类（美妆/食品/洗护…） | 精确分位带 KPI + 90 天时间线 + 真实 persona 引语 |
| **B** | 未校准结构化 | 消费品但弱接地（跨垂类/无强语料） | 同 A 的结构，但**标「未校准」、区间放宽** |
| **C** | LLM 情景推演 | 引擎演不了（B2B / 线下服务 / 全新物种） | **定性**情景（盘子/买家/渠道/采纳形状/风险），**无伪精确 KPI** |

**这套三档分诊，就是本次设计的灵魂。** 详见 `01-DESIGN-BRIEF.md`。

## 包里有什么

| 文件 | 给谁 | 怎么用 |
|------|------|--------|
| `00-START-HERE.md` | 你 | 本说明 |
| `01-DESIGN-BRIEF.md` | **open-design** | 主 brief。喂给 open-design（粘进 brief 输入 / 作为 DESIGN 输入）。**设计的灵魂在这** |
| `02-SCREENS-IA.md` | **open-design** | 逐屏信息架构 + 三档结果卡逐档规格 + 保留/砍清单。随 brief 一起给 |
| `03-API-CONTRACT.md` | 你 + 回传后的我 | 后端数据契约（真实 `LaunchReport` 结构）。设计阶段让它知道字段；回传后我据此接线 |
| `sample-A.json` | **open-design** | **真后端**捕获的 A 档完整报告（含真实 LLM persona 引语）。**上传给它做数据绑定，别让它编数字** |
| `sample-B.json` | **open-design** | B 档样例。**引擎结构为真**（同 A 管线）；分诊框架（未校准/放宽区间）为**设计目标**，文件内已逐条标注 |
| `sample-C.json` | **open-design** | C 档样例。**整份是设计目标**（后端尚未实现）；定义 C 档的定性产出契约 |
| `05-WIRE-BACK.md` | 回传后的我 | 你拿到设计产物后丢给我，我照这份接后端 + 改后端 + 起服务 |

> **数据诚实三色**：sample-A=**真**；sample-B=**真结构 + 标注的设计目标框架**；sample-C=**全设计目标**。三个文件顶部的 `_bundle_meta` 都逐字写明哪些是真、哪些是待建。这正是这个产品的红线——别让「测不准的猜测」看起来像「精确的预测」。

## 操作步骤（你来做）

### 第 1 步 · 在 open-design 生成几套备选设计
1. 打开 open-design（本地 daemon + 浏览器；它会调你 PATH 上已装的编码 CLI 出 HTML 产物）。
   - 若一时跑不起 open-design（它是 8000 文件的 monorepo，需 Node 24 + 现编 better-sqlite3），**这份 brief 是工具无关的**：粘进云端 Claude Design、或直接丢给任一编码 CLI，产物都是一样的「带 mock 数据的 HTML 壳」。
2. 把 `01-DESIGN-BRIEF.md` 全文作为 brief 输入。
3. **上传 `sample-A.json` / `sample-B.json` / `sample-C.json`** ——让它用**真实字段和量级**布局三档结果卡，别编数字。
4. 可选：把 `02-SCREENS-IA.md` 也一起给，或第二轮再给。
5. ⚠️ **不要**让它去读旧代码库继承旧视觉——我们要的是**新的、能把三档明显区分开**的设计。
6. 按 brief 的节奏：先出**整条主线的整体视觉**（落地 → 揭幕 → 结果卡 → 回放），重点让它**给 A/B/C 三档视觉区分的几套备选方案**供你选。
7. 选定后**导出**：standalone HTML 或 open-design 的产物目录。

### 第 2 步 · 丢回给我跑通
把导出的产物放进这个仓库，连同 `05-WIRE-BACK.md` 一起告诉我「按 WIRE-BACK 接后端」。我会：
- 把静态设计接到真 `/api/launch/*`（契约见 `03-API-CONTRACT.md`）；
- **据你选定的前端改造后端**：分诊路由、B 档放宽规则、**新建 C 档 LLM 情景推演模块**；
- 复用现成的 diorama 回放挂上「看电影回放」；
- 改服务脚本，本地 + 局域网起服务，验证 health 通。

## 一句话提醒
open-design 只产**前端可视产物**（带 mock 数据的漂亮壳）。**真后端、以及 C 档那条全新的 LLM 情景推演，由我（Claude Code）在你选定设计后接上 / 建出来**。这正是这个 bundle 的设计目的：前端先定形态，后端再据此长出来。
