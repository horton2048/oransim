## 3. 数据契约：`replay.json` v1

生产者 `replay_export.py`，消费者 `app/v3-final.html`。样例实物 `app/replay.json`（由 `fixtures/sample-data-full.json` 生成：60 souls / 25 城 / 20 KOL）。

| 字段 | 来源（/api/predict 响应） | 真/合成 |
|---|---|---|
| `meta.creative_id/caption/run_timestamp` | `scenario_summary` + T1_A2 | 真 |
| `meta.synthetic_fields` | 导出器声明 | — |
| `budget` / `platform_alloc` | `scenario_summary` | 真 |
| `kpis`（+现算 `aov`=revenue/conversions） | `kpis` | 真 |
| `funnel_percentiles` {A1..A5: p25/p50/p75} | `T1_A2_mc_funnel_prediction` | 真 |
| `per_platform`（含 `*_std`） | 直通 | 真 |
| `days` / `daily_total/paid/organic` / `peak_day` / `organic_share` / `branching_ratio` | `lifecycle` | 真 |
| `sentiment` | `predicted_sentiment` | 真 |
| `cities[]` {name,lat,lng,tier,weight} | persona `city_name` 计数 + 内置 gazetteer（约50城） | 名称/权重真，经纬度为映射；未命中进 `unmapped_cities` |
| `kols[]` | `T2_A1.selected_kols` | fans/reach/cost/roi/tier/niche 真；**platform/fire_day/city 确定性合成** |
| `souls[]`（按 t 升序） | `soul_quotes` + T3_A1 关联 | 字段真；**t 为曲线质量分布确定性合成**（`t_synthetic:true`），后端补 `timestamp` 后自动用真值 |

契约纪律：改 schema 必 bump `version` 并同步本表与 docstring；确定性是硬性质（同输入→逐字节同输出，无时钟无随机）；导出器容忍列表夹截断标记字符串（调试样本遗留特性）。

消费侧要点：HUD 计数器 = `kpis` 终值 × 曲线累计占比（`daily_total` 只借形状，单位是原始计数不是曝光量）；判决四条带读 `funnel_percentiles`（GMV 按 A4 比例缩放 revenue）；五幕阈值是相对实测峰值天的函数（meta.peak_day 与数组 argmax 不一致时以 argmax 为准）。

## 4. 样板内部结构（改造时的地图）

**v3-final.html**（约 2200 行单文件）：CSS+UI 骨架（含 4 个 overlay：brief/loading/empty/CDN 报错卡）→ Three.js importmap（unpkg r160，4s 看门狗）→ 内嵌 `window.__REPLAY_EMBED` → 取数三级（`?demo=1` 强制内嵌 / fetch `./replay.json` 带 4s abort+形状校验 / 回退内嵌+水印）→ 模块顶层 await 保证数据就位才初始化 → 双场景（A 地球 / B 微缩景观）→ 播放状态机（`simT/playing/mode`，`seek(t)` 全量重建）→ 判决/证词卡/诚实层（关于角标 z-index 66 > 判决 55）。

**v4-console.html**（约 960 行单文件）：左操作面板（12 控件：caption/budget/alloc 滑块/日期/时段/层级 chips/年龄 chips 等）→ `<script id="oransim-data">` 内嵌全量样本 → 「开始预演」→ 仪表盘（KPI 6 卡 / 漏斗五级置信带 / 分平台 / KOL 优选 / 敏感性龙卷风 / 宏观 13 项 / 灵魂墙 60 条分页 / 报告卡）→ `liveUpdate` 确定性联动（envFromForm/compute，标「确定性演算」）→ `#replaybtn` 全屏 iframe overlay 拉起 v3（懒加载、关闭清 src、ESC）。
