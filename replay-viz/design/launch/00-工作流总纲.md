## 1. 大框架（一句话钉死）

**后端数据 = 地基（定死，不迁就前端）。前端效果 = `replay-viz` 的 diorama 回放（定死，不重新设计）。本线的全部工作 = 在真实后端输出上，把这两端正确接起来。**

- 后端 = 上市模拟 `/api/launch/simulate` → `LaunchReport`（M0–M8 已全绿，是产品本体）。
- 前端效果 = `app/v3-final.html`（地球→40 城微缩景观→五幕→点光点出证词）+ `app/v4-console.html`（操作台）。
- 不做：不重设计 diorama；不补 12 个裸 schema 图表（独立排期）；不动推演引擎。

## 2. 真实数据地基（对照表，全部基于 `fixtures/launch_sample.json` 实测）

地基样本由 `scripts/capture_launch_sample.py` 抓取（mock 模式、POP=2000、确定性）。真实 `LaunchReport` 与 v3 消费契约（`app/v3-final.html::validReplay`）的逐字段对账：

### 2.1 真值直通（diorama 脊柱，launch 反而更强）
| v3 要的 | ← 真实 LaunchReport | 实测值 |
|---|---|---|
| 扩散曲线 `daily_total` | `timeline.daily_adopters` | 90 点真值（替 campaign 14 点） |
| 峰值天 | `timeline.peak_day` | 6 |
| 半衰/饱和/总盘 | `timeline.half_life` / `saturation_date` / `market_potential_m` | 6 / 11 / 160.0 |
| 判决三世界线 | `metrics.*.{p35,p50,p65}` | adopters 26.8/27.7/27.8 |
| 命名干预卡 | `what_breaks.intervention_cards[3]` | price_up_30 / no_kol_launch / competitor_response，各带 `{label,delta,branch,note}` |
| 诚实层 | `disclaimer` / `grounding_confidence` / `header.assumptions[6]` | 0.92 |
| 层级分布 | `who_buys.cate_segments[0].summary.effective_city_dist` | T1–T5+ = 8.9/15.9/22.8/28.1/24.3 |

### 2.2 硬缺口（v3 `validReplay` 会因此拒绝加载，必须解决）
| v3 硬性要 | 真实输出 | 处置 |
|---|---|---|
| `cities[]` 非空 + lat/lng/tier | **无 cities 块** | 从 `effective_city_dist`（层级占比，真锚点）+ GAZETTEER **确定性合成**点阵，打标 |
| `funnel_percentiles` A1/A3/A4 | **无五级漏斗**（launch 是 6 个独立指标带，概念不同） | **判决面板改 v3 直读 metrics**（见 §3 决策 B） |
| `per_platform` | launch 不分平台 | 从 spec `platform_alloc` 合成（无 ROI 真值→不展示 ROI） |
| `budget`（number） | 无顶层 budget | 取 spec `budget_hint_cny` |
| `kpis`（object） | 无 | 由 `metrics.*.p50` 派生（adopters→conversions、revenue→revenue…） |

### 2.3 软缺口（v3 能跑但共情层瘪）
| v3 用 | 真实输出 | 处置 |
|---|---|---|
| `kols[]` 开火点 | **无 kols 块** | 空数组（引爆幕降级）或用 spec KOL 名单合成，⚠待复核 |
| `souls[].city` | persona 无城市 | 按 `effective_city_dist` 确定性分配，打标 |
| `souls[].text` | persona 只有 `objection` | 直接用 `objection` 原话（逐字，不润色） |
| `souls[].sentiment` | 无 | 由 `purchase_intent_7d` / `will_try` 确定性派生 |
| `souls[].t` | 无 timestamp | 按扩散曲线质量分布确定性合成，`t_synthetic:true`（欠后端增量） |

## 3. 架构决策（已拍，理由进 DECISIONS）

**D-A/B：A 为主 + 判决面板局部 B。**
- **A（适配器扛，v3 不动）**：新建 `launch_replay_export.py`，纯函数把 `LaunchReport` 重塑成 v3 认的 `replay.json` v1 形状。地理/曲线/证词/KOL 的缺口全在适配器内**确定性合成 + `meta.synthetic_fields` 打标**。v3 的数据层（cities/daily/kols/souls/kpis）一行不改。
- **B（判决面板改 v3）**：`showVerdict()` + 第五幕旁白把 launch 的 P35/P50/P65 与 `metrics`（触达/试用/采纳/营收）**直读**、用对的标签；层级带改读 `effective_city_dist`；口碑改读 `objections_as_risk` + 置信度。
  - 为什么不全 A：把 P35/P50/P65 塞进 v3 现有的「p25/p50/p75 + A1/A3/A4 五级漏斗」槽位 = 伪造一个 launch 根本没有的漏斗结构，违反**诚实原则**。改 v3 这约 15 行是守红线的最小代价（视觉处理不变，只换数据源与标签）。

**其它已拍**：沿用 campaign 的 D1（挂主 SPA 第 10 tab，iframe）/ D3（iframe 隔离）/ D5（双主题）。取数路径见开发规范 §6。

## 4. 切刀分解（里程碑，依赖序线性，适合新手逐步推进）

| 里程碑 | 名称 | 产出 | 验收闸 | 依赖 |
|---|---|---|---|---|
| **FE-M0** | 地基 | `fixtures/launch_sample.json`（已抓）+ 本对照表 | 人工核对样本结构 | — |
| **FE-M1** | 适配器 | `launch_replay_export.py`：`LaunchReport`→`replay.json`，确定性、合成打标 | **pytest 逐字节比黄金 + 形状校验过 validReplay**（全自动） | M0 |
| **FE-M2** | 接 v3 取数 | v3 fetch 适配器输出 + 离线兜底 | Playwright：加载真数据、五幕可播、无 console 错 | M1 |
| **FE-M3** | 判决面板纠偏(B) | `showVerdict()` + 第五幕改 launch 原生 | Playwright/视觉：P35/P50/P65 + 触达/试用/采纳，无 p25/p75 误标 | M2 |
| **FE-M4** | 并入主 SPA | 第 10 tab iframe + 资产落位 + Three.js 自托管 | 人工 DoD：切 tab 看到本次回放、其余 tab 无回归 | M3 |

> 强弱分界：**M1 是纯数据线，能全自动门禁（像后端那样先红后绿、逐字节比黄金）**；M2–M4 是像素/集成，走 Playwright + 人工清单（HYBRID）。

## 5. 闭环怎么跑（方法论，照后端那套，按前端调）

1. **先红后绿**（仅 M1 适用）：先在 `tests/` 写 AT 让它红 → 写适配器让它绿。测试落仓库根 `tests/`，**禁止 `backend/tests/`**。
2. **可执行验收闸**：M1 = `pytest`；M2–M4 = Playwright 脚本 + 人工核对清单（`02-验收规范.md`）。「做完」= 对应 AT 全绿/全勾，不是「看着差不多」。
3. **黄金纪律**：`launch_replay.golden.json` 变更必须人工核对，DECISIONS 记一行；**绝不在循环里顺手重生黄金**。
4. **LEDGER 单一事实源**：每轮读 `LEDGER.md` 当前指针 → 做下一个未完成 AT → 验收闸绿 → 回写 LEDGER → commit（引用 AT 编号，mod/dev 分支，遵守 fork 工作流）。
5. **歧义自决**：计划没覆盖的，按四条铁律（字节级兼容 / 诚实原则 / 薄改原则 / 渐进纪律）自决、DECISIONS 记一行；产品级（合成口径 / KOL 取舍 / 阈值）标「⚠待复核」继续，不停等。
6. **里程碑复核**：一个里程碑全绿再进下一个；M2/M4 这类动 `frontend/` 与后端路由的，关键节点停下来给人确认（R5：session 是否持有完整报告）。

## 6. 红线（贯穿全线，违反即红）
- 合成字段必须①确定性②进 `meta.synthetic_fields`③前端可见处不冒充真值。
- 不伪造结构（如五级漏斗）——宁可改 v3 直读真值。
- `objection` / `note` 等原话**逐字不润色**。
- 弱字段（`season_window` / `audit_risk` / `calibrated:false`）展示需标「未校准」。
- 不动推演引擎；动 `frontend/` 是复制落位不是搬移（:8090 只服务 `frontend/`）。
