## 1. 适配器 `launch_replay_export.py`

- 位置：`replay-viz/launch_replay_export.py`（与 campaign `replay_export.py` 平级，**不复用同一文件**）。
- 核心：纯函数 `export(report: dict) -> dict`，输入真实 `LaunchReport`，输出 `replay.json` v1（v3 认的形状）。
- **确定性硬约束**：同输入逐字节同输出。禁用时钟 / 随机源 / 集合无序遍历。合成用 `stable_frac(key)` 式哈希（照搬 campaign `replay_export.py:77`）。
- 可复用 campaign 适配器的：`GAZETTEER`（25 城，按需补到覆盖各 tier）、`stable_frac`、`curve_time`、城市经纬度映射骨架。
- CLI：`python launch_replay_export.py [--in fixtures/launch_sample.json] [--out app/replay.json]`，默认读地基样本、写 v3 同目录。

## 3. 合成算法（确定性，全部进 `meta.synthetic_fields`）

### 3.1 funnel_percentiles 占位
`validReplay` 要求 `fp.A1_awareness && fp.A3_engagement && fp.A4_conversion`。判决面板改 B 后不再读它，但形状校验仍需通过。
→ 适配器写**最小占位**：`{A1_awareness, A3_engagement, A4_conversion}` 各填 `{p25,p50,p75}` 取自对应 metrics（unique_reach/trials/adopters 的 p35/p50/p65 映射），并在 `synthetic_fields` 标注「占位，判决面板已改读 metrics 真值」。⚠待复核：若嫌占位别扭，备选是放宽 `validReplay`（动 v3，归 B）。

### 3.2 cities 合成（有真锚点，非凭空）
输入：`cate_segments[0].summary.effective_city_dist`（T1–T5+ 占比）。
算法：
1. 目标城市数 N（默认 25，可配）。按各 tier 占比分配名额：`n_tier = round(N × pct_tier)`。
2. 从 GAZETTEER 按 tier 分组，确定性取前 `n_tier` 个（按城市名稳定排序）。
3. 每城 `weight` = 该 tier 占比 / 该 tier 城市数（保持层级总权重 = `effective_city_dist`）。
4. 经纬度取 GAZETTEER；未命中（GAZETTEER 缺该 tier 足够城市）→ 记 `unmapped` 并告警，不静默。
标注：`cities` 整体进 `synthetic_fields`，注明「坐标合成、层级占比来自 effective_city_dist 真值」。

### 3.3 kols 合成（⚠待复核：默认空数组）
launch 报告无 kols。默认 `kols: []`（引爆幕降级为「无具名 KOL，仅展示起势曲线」，第二幕旁白相应改）。
备选（需产品确认）：从 spec 的 KOL 名单造开火点，platform/fire_day/city 全合成打标。**先按空数组走，不阻塞。**

### 3.4 souls 合成
输入：`who_buys.persona_quotes[]`（will_try/would_pay_cny/objection/purchase_intent_7d）。每条产出：
- `text` = `objection`（逐字，不润色；空则给中性占位并标注）。
- `purchase_intent_7d` / `will_click(=will_try)` / `would_pay_cny` 直通（真）。
- `sentiment` = 由 `purchase_intent_7d` 确定性分档：≥0.5→1，≤0.05→-1，否则 0（记派生口径）。
- `city` = 按 `effective_city_dist` 加权、用 `stable_frac(objection)` 确定性指派一座 §3.2 城市（打标）。
- `persona` = 由 niche + tier 派生短标签（如「beauty·三线」），不杜撰具体人设。
- `t` = `curve_time(stable_frac(objection), daily_total)`，`t_synthetic:true`。
- 按 `t` 升序排序输出。

## 4. v3 改动点（决策 B，最小薄改）

仅改 `app/v3-final.html` 的判决相关，视觉/布局不动：
1. **`showVerdict()`（约 2076–2099 行）**：
   - 三条带改读 `DATA.metrics.{unique_reach,trials,adopters}` 的 `{p35,p50,p65}`，标签改「触达 / 试用 / 采纳」。
   - GMV 带读 `DATA.metrics.revenue.{p35,p50,p65}`，不再按 A4 比例缩放 revenue。
   - 层级带（tiers）已读 `DATA.cities` tier 权重，无需改（cities 已含真层级占比）。
   - 口碑（wom）：`net_sentiment_score` 改读置信度 + `objections_as_risk`（前 2 条）；无真值字段显「—」。
   - `per_platform` ROI：无真值 → 显占比、ROI 显「—」或隐藏该列。
2. **第五幕旁白（ACTS 末项，约 2002 行）**：「p25/p50/p75」→「P35/P50/P65」；可追加 `saturation_date` / `market_potential_m`。
3. **`bandHTML` 的 `p25/p75` 文案**（约 2075 行）：改「P35/P65」。
> 改动以 `DATA.metrics` 是否存在为分支（存在=launch 走新逻辑，不存在=campaign 走旧逻辑），保持对 campaign 数据不回归（薄改原则 + 字节级兼容）。

## 5. 单位与口径（写死，供 AT 判据）
- `daily_adopters` 是**原始采纳计数**（实测 5–17 量级，POP=2000），与 v3 `daily_total`「原始日活跃量、只借形状」口径一致 → **直通，不换算**。
- HUD 计数器 = `kpis` 终值 × 曲线累计占比（v3 现成逻辑），`kpis` 终值来自 metrics.p50。
- 真值字段**不得平滑/裁剪/补值/重排**（诚实红线，对应 AT-FE-1-04）。

## 6. 取数路径（M2/M4）
- **M2**：适配器 CLI 产出 `app/replay.json`，v3 `fetch('./replay.json')` + 内嵌兜底（现成三级序）。
- **M4**：后端加 `GET /api/launch/replay/{spec_id}`，路由内 `import launch_replay_export; export(report)`（转换逻辑全系统唯一一份，对齐 campaign D4）。前置读 `oransim/api.py` 确认 session/store 是否持有完整 `LaunchReport`（R5），不持有则路由内重跑 simulate 或缓存报告。⚠待复核：先 CLI 静态文件跑通 M2，路由留 M4。
